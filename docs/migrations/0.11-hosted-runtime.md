# Historical migration note: Heddle 0.11 hosted-runtime ownership

Heddle 0.11 retires the published `heddle-client` package. This note is the
only intentional historical reference to that package name; it is not a live
dependency or supported integration surface.

## Ownership map

| Before 0.11 | Heddle 0.11 owner |
|---|---|
| `heddle-client::credentials` store, schema, resolution, permissions, and atomic persistence | `heddle-cli-shared::credentials` |
| Native hosted session, Iroh connection/runtime, provider-plan negotiation, bounded concurrent download, positional assembly, resume, verification, and fallback | private `heddle-cli::hosted_runtime` module, with the narrow supported repo-event surface at `heddle-cli::client::repo_events` |
| Authentication device flow, `.hcred` verification, WebSocket status, and `whoami` command behavior | private `heddle-cli::hosted_runtime` module |
| Public protocol types, method descriptors, canonical request/provider-plan signing bytes, and framing identities | `heddle-api` 0.2.1 |
| Unused owner-authorization prototype and unused support/presence exports | removed; hosted/server policy stays in Weft |

`heddle-api` does not gain a transport, credential store, downloader, Iroh
dependency, or CLI policy. Consumers of hosted repository events use
`heddle-cli::client::repo_events`; other consumers that need a protocol
transport implement one against the API-owned method, framing, and signing
contracts.

The workspace intentionally remains on `heddle-api` 0.2.1. The relocated
runtime uses only contracts already present in that release; the physical
`StateId`, immutable thread ID, and structured ambiguous-change detail added in
0.2.2 are compatible but are not required by this migration.

## Credential migration

The file remains `~/.heddle/credentials.toml`, or
`$HEDDLE_HOME/credentials.toml` when `HEDDLE_HOME` is set. The TOML field
layout is unchanged. Readers still accept legacy `private_key`; writers emit
`private_key_pem`. Parent directories remain private, files remain mode 0600 on
Unix, and writes remain atomic.

Rust callers replace:

```rust
use heddle_client::credentials;
```

with:

```rust
use cli_shared::credentials;
```

where `cli_shared` is a dependency rename for `heddle-cli-shared = "0.11"`.

## Release and downstream substitutions

This is version 0.11.0 rather than 0.10.5 because removing a published crate
is a breaking pre-1.0 change. Heddle's workspace release policy keeps
publishable crates in lockstep, and its pre-1.0 contract policy signals
breaking changes with a minor bump.

Weft can replace every `git = "https://github.com/HeddleCo/heddle"` dependency
with the corresponding crates.io requirement:

```toml
cli-shared = { package = "heddle-cli-shared", version = "0.11", features = ["observability"] }
crypto = { package = "heddle-crypto", version = "0.11" }
objects = { package = "heddle-objects", version = "0.11", features = ["async-source"] }
oplog = { package = "heddle-oplog", version = "0.11", default-features = false }
refs = { package = "heddle-refs", version = "0.11", default-features = false }
repo = { package = "heddle-repo", version = "0.11", default-features = false, features = ["git-overlay", "native", "async-source"] }
semantic = { package = "heddle-semantic", version = "0.11", optional = true }
state_review = { package = "heddle-state-review", version = "0.11" }
wire = { package = "heddle-wire", version = "0.11", default-features = false }
```

Each Weft manifest keeps its existing feature selection; only `git` and `rev`
are replaced by `version`. The production `weftctl` credential import changes
to `cli_shared::credentials`. Its duplicate hosted-runtime dev-dependency is
unused and should be deleted.

Weft's direct Iroh fork pins can become registry dependencies at the same time:

```toml
iroh = { package = "heddleco-iroh", version = "0.1.0", default-features = false, features = ["tls-ring"] }
iroh-base = "=1.0.3"
iroh-relay = { version = "=1.0.3", default-features = false, features = ["server", "test-utils", "tls-ring"] }
```

The Heddle CLI also uses `heddleco-iroh` 0.1.0, with its
`unstable-custom-transports` and `unstable-custom-transport-backpressure`
features enabled. The support crates above are the upstream crates.io 1.0.3
releases; no HeddleCo git source remains in Heddle's resolved graph.

`weft-client-shim` remains published at 0.11 and remains a normal,
non-optional CLI dependency, so closed builds can continue replacing that
package through `[patch.crates-io]`.
